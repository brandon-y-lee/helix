### Confirmed reference problems to avoid

1. **Menu Escape is incomplete.** Opening focused the menu toggle and set body overflow to hidden. Escape left the menu visually open and the toggle named Close while releasing the body lock. A subsequent screenshot and menu scrolling confirmed the visible menu remained. Main content also remained in the accessibility snapshot. Do not claim modal isolation from its appearance.
2. **Mobile Search Escape loses focus.** Search opening focused the15 ×15 px Close control. The `serum` query settled to10 result rows. Escape closed the drawer but left focus on BODY. This was reproduced both after the menu sequence on Home and directly from the visible Search trigger on Shop. The earlier report's restored Search focus was not reliable across these fresh states.
3. **Empty Cart Escape loses focus.** Escape closed the mobile cart and left focus on BODY. The independent desktop check reproduced the same result. Never accept BODY or a hidden/offscreen header control as successful return focus.
4. **Desktop Search can return to an offscreen trigger.** After modest downward scrolling auto-hid the header, desktop Escape returned DOM focus to Search at y−108. Helix must reveal an appropriate header when needed before restoring focus.
5. **Sort Escape leaves the sheet visible.** After opening, focus stayed on the background Sort trigger. Escape released body scrolling but left the390 ×358 px sheet and backdrop visible; a later screenshot confirmed it remained. Close was mislabeled “Close Swatches Popup” and measured18 ×20 px. Helix's shared modal Sheet must eliminate these defects.
6. **Controls are often too small.** Observed mobile menu toggle25 ×18 px, Search17.2 ×19 px, cart21 ×19 px, Search Close15 ×15 px, Cart Close16 ×16 px, collection Sort112 ×17.4 px, layout controls24 ×26.5 px, compact product actions around29 px high. These visual rectangles are not Helix target sizes. Use at least44 px effective nonoverlapping targets and48 px primary actions as specified.
7. **The hero is sensitive to load/resize history.** Entering desktop and resizing to390 initially produced a219 px mobile hero. A fresh mobile load briefly produced812 px before media settled to487.5 px, matching the previous audit. This is a loading/resizing artifact, not established campaign drift. Helix should reserve correct media geometry and preserve it through resize. Both captures are retained so the short version cannot be mistaken for the target.

## M1 implementation acceptance checklist

- At320,390 and430 px, the64 px Helix bar has a centered wordmark, visible Search and quantity, and nonoverlapping controls. At920/921 px only the correct navigation surface is exposed. Desktop composition is preserved.
- At the top, middle and footer of Home, Shop and Super Serum, header show/hide never obscures a focus target; opening any overlay gives one visible close control and one focus trap.
- Menu fills the usable dynamic viewport, scrolls internally when needed, and exposes Shop, both correctly cropped collection tiles and all existing secondary destinations. Bottom account/support links remain reachable in short landscape.
- Direct Search focuses the appropriate entry control and displays customer-facing states. Escape and explicit Close return to the actual visible trigger. Menu→Search handoff removes the previous trap and returns to a visible equivalent control, never BODY.
- Cart body can grow and scroll while the bottom total/action stays reachable. The final row, errors and remove/quantity actions cannot hide behind the action region. Test empty, loading, unavailable and controlled populated states without claiming an unavailable checkout works.
- Menu, Search, Cart, Sort, Cookie and Waitlist never leave stacked focus traps or a stuck page scroll lock. Escape and explicit Close both restore the original page position. Short viewport/safe-area pressure must be checked separately from ordinary desktop resize.
- Footer order is wordmark→four visible navigation groups→compact service/status facts→privacy/locale/copyright. Navigation occupies the available width, long labels wrap, and only one semantic link tree is exposed at once. Preserve factual non-readiness disclosures.
- Every icon has a useful accessible name; every pointer target meets the approved44/48 px contract without overlapping adjacent hit areas. Visible keyboard focus is required. A screenshot alone does not establish this.

Home/discovery should be evaluated as a sequence of connected cards and contained rails: one card plus a clear preview, modest gaps, selectors next to updated content, natural copy height, and project-controlled media with preserved focal points. Collection density must not come at the expense of readable product identity or a usable CTA. Sort and Quick Buy require complete mobile sheets, not tiny desktop popups inside cards.

The72 px Rhode sticky bar supports Helix's64–76 px target, with the footer and modal suppression rules kept explicit. Media-first does not mean duplicating desktop imagery or filling blank space.

These observed heights must not become fixed CSS heights. Treat's approved4:3 ingredient image is an adaptation. The ingredient trigger still leaves focus on itself when its explanation is replaced, Escape does not dismiss, and explicit Close subsequently leaves document focus; Helix's inline reading-flow and focus requirements are intentional improvements. Routine03Glaze updates both principal image and small texture/name while keeping all five numbered controls in a row. The72 px purchase bar disappears as the footer enters; that reference condition is verified.

Service/About/System review must use the existing complete audit and then inspect all changed Helix routes. Useful navigation and natural reading flow are the relevant reference principles.
