Fresh task worktree setup contract

Drive the proposed task-start state model before any production script is changed. The demo shows what an agent knows, what is ready, and the exact command that resumes an interrupted setup.

Question: Does one resumable setup state machine make a new task worktree usable without hidden manual steps, while keeping Storefront builds and unselected browser downloads out of task creation?

What this represents

This is not a proposed screen or a list of prompts for an agent. It exposes the internal state of three future terminal commands. Buttons such as “Toolchain matches” simulate a result inside the command; the agent would not click or confirm those steps.

1. scripts/git/codex-task.sh start <task>
Creates the worktree and runs setup automatically.
2. scripts/git/codex-task.sh setup <worktree>
Used only to resume after setup stops.
3. pnpm verify:affected -- --base dev
Later installs only the selected browser and runs the selected plan.
