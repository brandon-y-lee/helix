# Domain maintenance

[CONTEXT-MAP.md](../../CONTEXT-MAP.md) routes Helix vocabulary to its owning glossary. Use those terms in issues, code, tests, and handoffs; avoid synonyms explicitly excluded by the glossary. Do not create a second root glossary or duplicate definitions.

Add a term only when its meaning is resolved, Helix-specific, durable, and justified by the task. Define finite vocabulary values only when agents must distinguish non-obvious, stable meanings. Do not mirror schemas, provider objects, routes, or generic technical vocabulary. Related contexts may link to a term's owner.

Keep specifications and implementation decisions in their canonical sources. Surface ADR conflicts explicitly before overriding them. Missing context-scoped ADR directories need no scaffolding.
