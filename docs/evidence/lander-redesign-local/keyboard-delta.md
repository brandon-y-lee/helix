# Local prototype delta — keyboard/hover preservation

During 390px browser verification, pressing End on Innovation moved focus to Sustainability but active content reverted to Innovation: the changed title height moved the pointer onto another row and generated a pointer-enter selection while keyboard navigation was in progress. This is an actionable affected interaction concern, not approved behavior.

Proposed minimal fix: HomeThreePrinciples tracks whether the last interaction was keyboard navigation. All keyboard events and focus activation mark keyboard intent before selection, including Tab/Shift+Tab focus changes. Pointer click/down restores pointer intent. Ignore pointer-enter activation in that mode until actual pointer movement/down restores pointer intent. Actual pointer movement over a label also activates that label even when its earlier pointer-enter was ignored. Keep ordinary hover, tap/click, focus, arrows/Home/End; don't change content or roles. Add a focused component test for keyboard selection resisting layout-induced pointer-enter, then real pointer movement restoring hover over that same label; include focus/Tab-mode activation and touch/click.
