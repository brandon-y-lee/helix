# Complete the helix rebrand through coordinated identifier migrations

The helix rebrand will finish without active Mei Pelle names in application code, tests, configuration, current database objects or data, or remote resources, and without application-managed legacy compatibility. Active Rewards & Referrals identifiers will use rewards language instead of loyalty language. Resources that cannot be renamed in place will use a temporary create, copy, switch, verify, and delete sequence; the temporary bridge must be removed before the rebrand is complete. Applied migration files, immutable real audit history, opaque provider-assigned identifiers, and provider-managed redirects remain intact because they are historical or external identity rather than active brand compatibility.
