# Separate routine browser verification from bounded Product-media verification

Routine Browser Verification uses live Storefront facts but replaces Supabase-hosted Product-media responses with small valid test media, fails when a real Product-media body escapes containment, and reports the requests it contained. Real Product-media Verification is a separate credential-free check of every distinct public Product-media URL in the active Storefront: it permits one 32-byte range response per URL, derives its total budget from the current URL count, and proves the approved origin, bounded response, media type and signature, nonzero object size, and public cache policy. This split preserves browser-behavior coverage and Customer-path verification without making routine local or CI runs download full Product media through cold caches.

Real Product-media Verification is required before Publish and runs again after Publish, daily, and on manual request. A later failure alerts the operator and uses the Storefront media fallback without changing Catalog Status or other Catalog facts; Routine Browser Verification remains a pull-request gate but does not repeat after an identical Git tree enters `dev` or `main`. Production Artifact Verification retains the dedicated lifecycle ownership established by ADR-0001.
