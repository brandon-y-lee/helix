## Deploy and reconcile before contraction

1. Coordinate a bounded pause in Catalog publication and a drain of route-only HTTP deliveries. The new webhook endpoint rejects the retired table, so leaving its old trigger generating requests during the cutover is not an acceptable steady state. Keep the six current Catalog HTTP hooks, payment processing and customer activity operating.
2. Deploy the canonical PDP/metadata and alias-free Search projection at the recorded SHA. 3. Verify current Product pages and metadata from that deployment without the public resolver/ledger read. A meaningful ingredient query may still match a component of a former name; the removed behavior is exact obsolete identity/alias matching.

## Contract last

Review the final inventory and independent evidence from the same verified deployment. Load `product-url-preflight.sql` and `product-url-contract.sql` in the same database session. Begin an explicit transaction, set local `lock_timeout` to `5s` and `statement_timeout` to `120s`, then call `pg_temp.contract_product_urls(reviewed_inventory, verified_evidence)`. Use structured bound JSON values; the operation does not substitute secrets into shell command text.

The evidence object requires the approved `projectRef`, `stage: "canonical-consumers-search-reconciled"`, exact 40-character `sourceSha`, equal `verifiedDeploymentSha`, actual `deploymentId`, and true `canonicalConsumersVerified`, `searchVerified`, `catalogWritesPaused`, and `routeDeliveriesDrained`. These are required attestations, not independently proved by SQL; retain the observations that justify them. Synthetic SHAs used by local tests are never operational evidence.

The function rechecks the exact reviewed inventory under bounded locks, refuses changed/unknown resolver bodies, signatures, callers, tracked dependencies, grants, policies or route trigger shape, and drops only the exact managed route HTTP trigger and `resolve_product_slug(text)` with `RESTRICT`. It removes public SELECT/policy, keeps RLS and service-role read, and verifies private reservation rows and integrity functions/triggers did not change. Unexpected state or partial prior contraction requires reviewed recovery; no cascading deletion or integrity-trigger removal is allowed. A verified already-contracted state returns an explicit no-op.

Commit only after the returned postflight is correct. Verify actual anonymous and authenticated table/RPC denial, service-only history inspection, current URL/metadata/Search behavior and retired hook absence. Resume Catalog publication, then verify ordinary publication/search/cache refresh. Preserve historical Product/Variant IDs, Orders, Published Revisions, audit facts, applied migrations and required media.

After contraction an old alias-dependent app/Search reader is not a standalone rollback. Deploy a matching canonical consumer or restore the corresponding reviewed API/access contract with its exact recovery plan before using an old deployment. Do not reintroduce aliases silently or alter historical facts.
