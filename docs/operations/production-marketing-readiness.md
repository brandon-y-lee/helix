# First production welcome email retirement

Spec #622 retires the confirmed-welcome program. The storefront no longer offers Email preferences or the production enrollment, confirmation and withdrawal pages and APIs. Demo links may return 404. The [footer newsletter](newsletter-signup.md) collects addresses separately. Shared lifecycle and legacy consent links generated by the current app use `/marketing/consent` and require an explicit action. Shared one-click unsubscribe remains available.

## On the approved release

1. Verify that stored production dispatch and enrollment are paused before promotion. Keep both paused throughout rollback, including if an older serving artifact returns. Preserve the consent, suppression, message and receipt records. Shared delivery history remains available to reconcile an already-admitted send.
2. Verify the retired pages and endpoints return 404. The authenticated `confirmed-welcome` schedule still checks the serving deployment and erases expired message payloads. It performs cleanup for either value of the former dispatch flag.
3. Keep the signed `/api/webhooks/marketing-production` callback and its Support routing active under their existing controls. The callback still processes restrictions and reconciles previously admitted messages. Review outstanding receipts and preference holds through the authorized production status endpoint. Preserve the original provider identity and treat unresolved outcomes as uncertain.
4. Check the separate footer newsletter and the shared confirmation, withdrawal and one-click paths. The shared delivery service blocks the retired sandbox welcome series and skips frozen marketing messages that still contain a retired action URL. An already-admitted payload retains its original provider key and content until normal expiry.
